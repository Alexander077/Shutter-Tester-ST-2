Это проект для платы eps32-s2 mini на ESP IDF 5.4. Это тестер выдержкит для пленочных камер. В этом проекте есть АПИ для последователоьного COM порта. Сейчас мне нужно создать Пайтон скрипт для всеобъемлющего тестирования этого АПИ. У меня есть уже скрипт для тестирования части АПИ, которая отвечает за работу с записями измерений, которые храняться на устройстве. Также есть скрипт, который тестирует АПИ обновления прошивки. Я тебе прикреплю их для твоей оседомленности. 

Мне теперь нужен единый скрипт, с помощью которого можно будет тестировать все АПИ. Скрипт должен выводить меню, в котором можно выбрать, что я сейчас хочу протестировать: настройку света, перевод устройства в режим измерения выдержки и получения результата измерения, тестирование работы с сохраненными на устройстве записями измерений, а также пункт для тестирования обновления прошивки.

Когда пользователь выбирает пункт перевода устройства в режим настройки света, то нужно послать запрос на устрорйство, чтобы оно перешло в режим настройки света. После перехода в этот режим устройство начнет слать статус по свету. Нужно выводить форматированый JSON, который присылает устройство, но не так, чтобы каждый новый JSON печатался с новой строки, а чтобы каждый новый JSON пеертирал старый, чтобы не появлялся скроллбар. Если теперь пользователь нажмет Esc, то нужно перейти обратно в главное меню.

Если пользователь выбирает пункт меню тестирования режима измерения выдержки, то нужно перед переводом устройства в режим измерения выдержки запросить у пользователя размер кадра, и, если уместно, то направление движения шторок. После перехода в режим измерения нужно ждать ответа от устройства с результатами измерений. Как они прийдут(это можыт быть через любой промежуток времени), то их нужно вывести в виде форматированного JSON. Если пользователь нажмет Esc, пока ждет результатов измерений или когда результаты уже выведены, то нужно выйти в главное меню.

С тестированием АПИ по работе с записями измерений на устройстве можно сдлеать похоже на то, что уже есть в скрипте тестирования записей, можешь взять оттуда перечень тестов. Когда пользователь выбирает пункт тестирования работы с записями, то нужно в автоматическом режиме, похоже на то, что уже есть в скрипте тестирования работы с записями, прогнать основные операции с выводм логов. После прогона всех операций нужно ждать, пока пользователь нажет Esc, и выйти в главное меню. 

С пунктом тестирования обновления прошивки устройства можно поступить так, как уже есть в соответствующем скрипте.

Скрипт сделай, чтобы в нем все было на английском.

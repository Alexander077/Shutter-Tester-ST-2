# Задание 6: Имена сохранённых измерений и серий измерений

## Контекст проекта

Это прошивка для платы ESP32 (ESP-IDF 5.4.0 + компонент Arduino-ESP32) — прибор для измерения выдержки плёночных фотоаппаратов (Shutter Tester ST-2). Прибор регистрирует импульсы света от двух фотодатчиков, рассчитывает времена/скорости шторок, отображает результаты на TFT-дисплее ST7735 128×160 (шрифт `u8g2_font_6x13_tf`, 6 px на символ, ~21 символ в строку) и сохраняет измерения в LittleFS.

Управление: **один энкодер** (класс `AlexEncoder`, клики детента, счётчик `AlexEncoder::counter`) и **одна кнопка** (класс `AlexButton`: короткий клик `isClicked()`, удержание `isHolded()` фиксируется через 500 мс, сырое состояние пина `isDown()`). Кнопка опрашивается из ISR-таймера 300 Гц через `button.tick()`.

Хранилище: `main/recordsManagement/` — записи фиксированного размера в `/littlefs/records.bin` (100 слотов, `StoredMeasuredResult`) и `/littlefs/seriesRecords.bin` (100 слотов, `StoredMeasuredSeries`); шаблонный менеджер `RecordsStorageManagerT<RecordT>` читает/пишет файл блоками `sizeof(RecordT)`. В корне проекта лежит `film_cameras_list.txt` — словарь названий фотокамер (~1160 строк, одна камера на строку, ~16.6 КБ).

Команда сборки:

```
cmd /c "C:\Users\Alex\esp\v5.4\esp-idf\export.bat && cd /d "d:\Programming\Shutter Tester ST-2\Main Unit" && idf.py build 2>&1"
```

После изменения функционала нужно обновлять `.clinerules/ai-rules.md`, чтобы он был in sync с проектом.

## Задача

Дать пользователю возможность задавать имя (максимум **40 символов**) для сохранённого измерения и серии измерений — как при сохранении, так и позже при просмотре ранее сохранённой записи.

### 1. Хранение имени

- Добавить в структуры сохраняемых записей (`StoredMeasuredResult`, `StoredMeasuredSeries`) поле `char name[41]` (40 символов + NUL). Пустая строка = имя не задано (в UI показывается номер записи, как раньше).
- Изменение размера записи ломает совместимость с уже существующими файлами `records.bin` / `seriesRecords.bin` — обязательна **миграция при старте**: если размер файла соответствует старому формату (структура без поля `name`), перечитать его по старому размеру записи и переписать в новом формате. При этом в поле `name` каждой **валидной** записи записать форматированный номер записи (тот же формат, что раньше использовался для отображения, т.е. `"%04d"` → «0002»). Удалённые/пустые слоты — пустое имя. Старые форматы зафиксировать в отдельном заголовке (байт-в-байт идентичные прежним). Файлы неожидаемого размера — пересоздавать с нуля с логом.

### 2. Словарь автодополнения

- Встроить `film_cameras_list.txt` в образ прошивки через `EMBED_TXTFILES` в `main/CMakeLists.txt` (символы строятся от базового имени файла: `_binary_film_cameras_list_txt_start/end`). Обновление словаря = правка файла + пересборка.
- Поиск подсказки: первое имя из словаря, начинающееся с введённого префикса (сравнение регистрозависимое; поддержать переносы строк `\n`/`\r\n`/`\r`). Линейный скан по 16 КБ во flash — приемлемо, RAM не расходуется.

### 3. Страница выбора имени при сохранении

Когда пользователь выбирает «Yes» (а также «Overwrite oldest», «Overwrite newest», «Sel. rec. to overwrite») в меню сохранения после измерения/серии — показать страницу с двумя пунктами:

- **«Save as '0002'»** — в `name` записывается строка вида форматированного номера записи («0002», как раньше формировалось отображаемое имя) и запись сразу сохраняется с этим именем;
- **«Save as...»** — открывается экран посимвольного ввода имени (см. п. 4). Cancel в редакторе возвращает обратно на эту страницу выбора.

Номер записи для пункта «Save as 'NNNN'» нужно предсказывать до сохранения: для «Yes» — `max(валидных номеров)+1` (менеджер нумерует новые записи именно так), для перезаписей — min/max (oldest/newest) либо номер выбранной записи. Сообщение после сохранения: «Saved: <имя>» (имя обрезать под ширину экрана ~21 символ, длинное — с «...»).

### 4. Экран посимвольного ввода имени

Состояние: буфер до 40 символов, позиция курсора, «текущий редактируемый символ» в курсоре, режим (ввод букв / удаление), активная подсказка, прокрутка окна (на экране видно ~19 символов, строка автопрокручивается).

Управление (жесты):

1. **Поворот энкодера** — циклическая прокрутка текущего символа в курсоре через алфавит: `A-Z a-z 0-9 пробел - ( ) + < > { } [ ] / #`. Подсказка автодополнения пересчитывается мгновенно при каждом изменении символа.
2. **Клик кнопки** — зафиксировать символ, курсор к следующей позиции; следующий символ **подхватывается из строки-подсказки** (но пользователь может его повернуть и заменить).
3. **Удержание кнопки + поворот энкодера** — перемещение курсора влево/вправо (и в режиме ввода, и в режиме удаления). За концом строки курсор уводится в два виртуальных «слота»: **«Ok»** и **«Cancel»**; клик по ним подтверждает/отменяет ввод.
4. **Удержание без поворота, отпускание через ≥700 мс** — переключение в **режим удаления** (и обратно). В режиме удаления: курсор отображается **мигающей скобкой «<»**; каждый клик стирает символ слева от курсора и сдвигает курсор влево; поворот без удержания ничего не меняет; удержание+поворот двигает курсор как обычно.
5. **«Ok» при пустом имени** — не подтверждает ввод: строка имени мигает фоном (белый↔чёрный несколько раз), редактор остаётся открытым.

Отображение: введённые символы — белым, редактируемый символ — инверсией (чёрным на белом), продолжение подсказки — серым (после введённой части), счётчик длины «N/40», индикатор режима (ввод/удаление), при «дозревшем» удержании ≥700 мс — мигание индикатора (обратная связь перед отпусканием).

Сценарий автодополнения (обязателен): пользователь вводит «N» → сразу видит «N» белым + «ikon 28Ti» серым (первое совпадение из словаря). Клик — фиксируется «N», следующий символ «i» подхвачен из подсказки. Пользователь поворачивает «i»→«o» → подсказка мгновенно меняется на «Norita 66» («No» + серое «rita 66»). Далее соглашается кликами по буквам «Norita», а на месте «66» вводит «1» поворотом. Т.е. подсказка предлагается, но не мешает вводить свой текст. Важный нюанс: при уходе курсора за конец строки (в слот Ok) символ, который пользователь явно повернул энкодером, должен зафиксироваться (сценарий «Norita 1»), а символ, лишь подхваченный из подсказки, — нет.

### 5. Интеграция в UI

- Переименование при просмотре: в экранах просмотра сохранённых записей (`ViewRecordsScreen`) в меню «What's next?» после результата добавить пункты **«Rename record»** / **«Rename series»** — редактор открывается с уже введённым текущим именем, «Ok» сохраняет через `saveOrUpdateRecord()`, «Cancel» — без изменений.
- Списки выбора записей (`MeasurementResultRecordSelectionScreen`) показывают **имя записи** (обрезанное под ширину строки ~16 символов + «...»), если имя задано, иначе — форматированный номер, как раньше.
- Сообщения «Record renamed» / «Series renamed» / «Failed to rename ...» после переименования.

### 6. Ограничения и требования

- **Серийный API не трогать**: команды и ответы не меняются, поле `name` в JSON не добавляется. Записи, сохранённые через API, получают пустое имя (показываются номером).
- `AlexButton` можно доработать под нужды распознавания жестов (для различения «удержание с поворотом / без» и порога 700 мс нужна собственная машина жестов поверх дебаунс-устойчивого состояния кнопки, например метод `isDownStable()`), но нельзя сломать существующее поведение `isClicked()`; отложенные клики/удержания не должны «протекать» в следующие экраны.
- Все экраны обязаны проверять флаг `isApiRequestReceived` и корректно выходить при запросе API (как остальные экраны проекта).
- Файл словаря должен остаться в корне проекта (не копировать его в `main/`).
- Сборка должна проходить без новых ошибок; предупреждения, существовавшие до изменения, допускаются.
- Обновить `.clinerules/ai-rules.md` (описания новых/изменённых файлов и потоков).

## Критерии приёмки

1. Сборка `idf.py build` проходит успешно.
2. На устройстве со старой прошивкой и сохранёнными записями: после обновления записи сохранены, их имена = старые форматированные номера («0002»...).
3. Сохранение (все 4 варианта) показывает страницу «Save as 'NNNN'» / «Save as...»; выбор первого — сохраняет с именем-номером, второго — редактор имени.
4. В редакторе работает сценарий «N»→«Nikon 28Ti»→клик→«i»→поворот на «o»→«Norita 66» с посимвольным соглашением и заменой «66» на «1».
5. Удержание+поворот двигает курсор; удержание ≥700 мс без поворота — режим удаления с мигающим «<» и стиранием кликом; выход — тем же жестом.
6. За концом строки — слоты «Ok»/«Cancel»; «Ok» с пустым именем мигает строкой и не подтверждает.
7. Переименование записи/серии из экрана просмотра сохраняет новое имя, и оно отображается в списках.
8. Серийный API работает как раньше (команды и формат ответов не изменились).
